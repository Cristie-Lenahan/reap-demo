# Reap API compatibility audit · 9 October 2026

The prototype was designed around Reap's purchase sequence, but it remains a **concept mock, not an API integration or schema-compatible adapter**. `model.js` has an in-memory `MockReapAdapter`; `app.js` renders simulated checkout results. No HTTP request, enrollment, key, payment or merchant order was used. The existing small UI and policy model can be reused, but connecting Reap requires backend and UI work beyond swapping a URL.

Codex checked the official guides; the independent read-only reviewer checked the published references and OpenAPI against the actual source. The mapping below records the required future implementation, not completed functionality.

## Durable execution and cancellation

Reap's idempotency keys last 24 hours and allow at most 255 characters. Persist one key per logical enrollment, quote and checkout operation, reuse it after uncertain failures, and hold a durable care-request lock beyond retention. The current key embeds an entire cart fingerprint without a length bound; use a compact stable ID. In-memory maps and reset/reload guards only demonstrate session behavior. [Idempotency reference](https://docs.reap.global/api-reference/idempotency)

The mock invents a CANCELLED state and can stop a local timer. The published checkout status contract does not provide an equivalent cancellation operation. A live “back” or “close” action must retain the checkout ID and reconcile status before allowing another attempt; never promise it stopped payment. [Lifecycle](https://docs.reap.global/agentic-payments/lifecycle)

Physical-goods shipping details need first/last name, E.164 phone, address line, city and country; include Singapore postal code. Normalize API money objects deliberately instead of sending the demo's cents directly. The published reference uses `https://sg.sandbox.api.reap.global`, Bearer authentication and `Reap-Version: 2025-02-14`; confirm the enabled environment/version with the team. [Published OpenAPI](https://docs.reap.global/api-reference/openapi.json)

## Availability and documentation questions

The current one-time guide describes a ONE_TIME mandate, but the checkout request schema has no mandate field. Recurring prose describes reuse while navigation still marks it “Coming soon.” Confirm those features with Reap; neither blanket availability nor unavailability is established by the conflicting pages. The demo now states only its own per-purchase owner-approval scope. [One-time guide](https://docs.reap.global/agentic-payments/one-time-purchases), [recurring guide](https://docs.reap.global/agentic-payments/recurring-purchases), [checkout reference](https://docs.reap.global/api-reference/agentic/create-checkout)

External checkout URLs are documented for domains allowlisted for the integration. Discovery-only sellers stay outside this demo's checkout path; do not substitute scraped checkout or raw card details. [One-time guide](https://docs.reap.global/agentic-payments/one-time-purchases)

The supplied event directory lists Kohepets; this audit could not independently reopen the microsite. Exact SKU, stock, delivery and merchant checkout support remain untested.
